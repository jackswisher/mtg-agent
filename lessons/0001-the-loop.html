Lesson 01 · mtg-agent

The loop you are going to optimise

Every hour on this project goes into making one five-line loop produce better numbers.

You know Magic. You know Python. You don't yet know Gymnasium — and Gymnasium is the shape of this repo. Every architectural oddity in mtg-agent exists to satisfy a contract that fits on one page.

1. The contract

A Gymnasium Env promises four things (Env API docs):

MemberPromise
observation_spaceThe shape of what the agent sees
action_spaceThe shape of what the agent may do
reset(seed)Start an episode → (obs, info)
step(action)Advance → (obs, reward, terminated, truncated, info)

That's it. Everything else — PPO, vectorised envs, callbacks, the whole Stable-Baselines3 stack — is machinery bolted onto those four members.

The one gotcha for newcomers

terminated and truncated are not the same thing. terminated means the episode reached a real end state — someone's life hit zero. truncated means an artificial cutoff fired, here the max_turns limit. Old Gym had a single done flag and conflated them; Gymnasium split them in v0.26 because the end-of-episode value bootstrap is mathematically different in each case (migration guide). A turn-limit truncation is not a loss. Train as though it were and you teach your agent that time running out is a defeat to avoid — exactly wrong for a control deck.

3. The action mask is the whole game

Magic has an enormous nominal action space and a tiny real one. You can name 478 things; at any given instant maybe three are legal. Gymnasium has no concept of this — Discrete(478) means "any int from 0 to 477, always."

So the repo publishes a binary legality vector in info, and the policy multiplies its logits by that vector before sampling. Illegal actions get probability zero, and the gradient never flows through them (MaskablePPO).

obs, info = env.reset(seed=42)
mask = info["action_mask"]        # int8, shape (478,)

import numpy as np
np.flatnonzero(mask)              # array([1, 2])  <- KEEP_HAND, MULLIGAN

The mask lives in info, not in the observation. It is metadata about what is allowed, not information about the position.

The uncomfortable fact

I measured 20 random episodes on the default settings. Across 4,093 steps, 49% had exactly one legal action — mean 2.81, max 11. Turn on the simplification flags (auto_resolve=True) and it gets starker: 72% of steps offer a single choice, mean 1.74.

Half or more of every rollout is the agent being marched through PASS with no decision to make, consuming training budget and contributing nothing. A property of the environment, not a bug — but the first thing to look at when training feels slow.

Reproduce it yourself:

uv run python -c "
import numpy as np, collections
from mtg.env import MTGEnv
from mtg.agents import RandomAgent
env = MTGEnv(deck_archetype='mono_red_aggro',
             opponent_archetype='azorius_control', max_turns=10)
agent, counts = RandomAgent(seed=0), []
for ep in range(20):
    obs, info = env.reset(seed=ep)
    done = False
    while not done:
        counts.append(int(info['action_mask'].sum()))
        a = agent.select_action(obs, info['action_mask'], info)
        obs, r, term, trunc, info = env.step(a)
        done = term or trunc
c = collections.Counter(counts)
print('steps', len(counts), '| mean %.2f' % np.mean(counts),
      '| single-choice %.0f%%' % (100 * c[1] / len(counts)))
"

4. The loop

What training optimises, what evaluation measures, and what every workflow in the README ultimately calls:

obs, info = env.reset(seed=42)
done = False

while not done:
    action = agent.select_action(obs, info["action_mask"], info)
    obs, reward, terminated, truncated, info = env.step(action)
    done = terminated or truncated

Five lines. The mission — a bot that plays meta decks well — is making select_action better, and making the obs, mask, and reward flowing into it faithful to real Magic.

Check yourself

Q1Your control deck survives to the max_turns cutoff without either player dying. What does step() return?

Truncation — an artificial time limit fired. terminated is reserved for a real terminal position, which in MTG means a player lost. Getting this backwards poisons the value bootstrap at episode end.

Q2Where does an agent read the list of currently legal actions?

info["action_mask"], an int8 array of shape (478,). env.action_space only ever reports Discrete(478). Legality is per-state, so it travels in info.

Q3You add a card whose effect the engine has never modelled. Which file holds the code that makes it actually do something on resolution?

card_definitions.py declares that a card exists and what it costs. rules.py → _resolve_spell is the ~470-line switch deciding what happens on resolution. Adding a card touches both.

Recall, no scrolling. Write out the five values step() returns, in order, and say in one line what each is for.

obs — what the agent sees next (3077 floats).
reward — scalar feedback for the action just taken.
terminated — the game genuinely ended (someone lost).
truncated — an artificial limit fired (max_turns).
info — everything else, critically action_mask.

If you wrote done instead of the two flags, you learned Gym, not Gymnasium. Fix that now; it will bite you at every episode boundary.
